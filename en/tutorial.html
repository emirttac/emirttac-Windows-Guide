Tutorial: Step by Step

Who is this for? This page is for people who want to edit Windows installation media on their own computer but have never done it before. For every step, it explains what we are doing, why, and how to check the result.

What we will do in short: Open the Windows 11 installation ISO, change the installation file inside it (install.wim) in a working folder, and then build a new ISO from those changes. The changes include removing some preinstalled apps and, optionally, writing default user settings.

Which versions? Windows 11 25H2 and 26H2. The steps are the same for both: 26H2 arrives as a small "enablement" package on top of 25H2 and shares the same servicing branch. To tell which version your ISO is, check the ISO file name (it may contain 25H2 or 26H2). If you are unsure, look at the Version line in the dism /Get-ImageInfo output in Step 3: 10.0.26200.x means 25H2, 10.0.26300.x means 26H2.

What you need before you start:

  • A Command Prompt opened as administrator: type cmd in the Start menu, right-click it, and select Run as administrator.
  • About 30 GB of free space. The ISO, the copied media, the working copy, and the new ISO together can take that much room.
  • A backup of the original Windows ISO file.
  • Patience. DISM steps may look frozen for a while; wait for the progress percentage to move.

About the commands: Paths such as C:\Mod are examples. Replace placeholders in angle brackets such as <N> with your own value, and do not type the brackets.

Warning: Test this guide in a virtual machine first; do not apply it to a real device or distribution media before testing. Removing Microsoft Edge and WebView2, disabling security features, and activation bypass steps are outside the scope of this guide (see 1 and 10.4).

Step 1: ADK and oscdimg installation

What we are doing here: We install Microsoft's free Windows ADK toolkit. The only part we need is oscdimg.exe, the tool that builds the new ISO file.

  • From Microsoft's Windows ADK installation page, download ADK 10.1.26100.9457 (September 2026). This version supports Windows 11 25H2 and 26H2. If you downloaded an earlier installer, download the setup again; Microsoft recommends this version over 10.1.26100.2454.
  • On the installer screen, leave only the Deployment Tools box checked. The other features are not needed for this guide.
  • Caution: the 10.1.28000.x series (October 2026) is only for Windows 11 26H1. Do not use it for 25H2 or 26H2.
  • If you use WSIM, also apply the ADK patch released for CVE-2026-25166 (details in 3.3).
  • After installation, oscdimg.exe is usually in this folder:
    C:\Program Files (x86)\Windows Kits\10\Assessment and Deployment Kit\Deployment Tools\amd64\Oscdimg\oscdimg.exe
    If you installed to another location, search for oscdimg.exe in File Explorer and note its full path.

Check: Type the full path in quotes in Command Prompt and run it without parameters. If usage information appears, the tool works.

Step 2: Preparing the working environment

What we are doing here: We set up a separate working area so we can make changes without touching the original ISO. We copy the ISO's contents and make our changes in that copy.

  • In an administrator Command Prompt, create two folders:
mkdir C:\Mod\Gecici
mkdir C:\Mod\Medya
  • Gecici is the empty folder where we will mount the WIM file. Medya is the copy of the ISO contents.
  • Avoid spaces and non-ASCII characters in paths, and do not use protected locations such as Documents (3.1).
  • Right-click the Windows 11 ISO and select Mount. A new drive letter (for example E:) appears; note it.
  • Copy all contents of the ISO into the Medya folder. Replace E: with your own drive letter:
xcopy E:\* C:\Mod\Medya\ /E /H /K /Y
  • Copying takes a few minutes. When it finishes, C:\Mod\Medya should contain the boot, efi, and sources folders.
  • Check the name of the installation file on your media, then follow the path that matches it:
dir C:\Mod\Medya\sources\install.*
  • If the output shows install.wim, follow Path A below. If it shows install.esd, follow Path B: .esd is a compressed format that cannot be edited directly, so it must first be converted to .wim.

Path A: if install.wim is present

  • Remove the read-only attribute from the file and take ownership of it, then give the Administrators group write permission. Without these, you cannot modify the file:
attrib -r "C:\Mod\Medya\sources\install.wim"
takeown /F "C:\Mod\Medya\sources\install.wim"
icacls "C:\Mod\Medya\sources\install.wim" /grant Administrators:F
  • Create the working copy. The original stays in Medya\sources as a backup; do not delete it until Step 7:
copy "C:\Mod\Medya\sources\install.wim" "C:\Mod\install.wim"

Path B: if only install.esd is present

  • List the editions on the media and note the number (index) of the edition you want:
dism /Get-WimInfo /WimFile:"C:\Mod\Medya\sources\install.esd"
  • Export the edition you chose to a new .wim file. Replace <N> with the index number. This step temporarily uses extra disk space:
dism /Export-Image /SourceImageFile:"C:\Mod\Medya\sources\install.esd" /SourceIndex:<N> /DestinationImageFile:"C:\Mod\install.wim" /Compress:max /CheckIntegrity
  • This command creates C:\Mod\install.wim directly, which is your working copy, so skip the copy command from Path A. The new file contains only one edition, and its index is usually 1.

Check: dir C:\Mod\install.wim should list the file. Its size depends on the release, but it is roughly 7 GB.

Step 3: Finding the WIM index and mounting

What we are doing here: A .wim file can contain several Windows editions (Home, Pro, Education, and so on). Each one has a number, called the index. We pick the edition by its number and mount the file into a folder, which lets us reach and change the files inside.

  • Get the list of editions in the file:
dism /Get-ImageInfo /ImageFile:"C:\Mod\install.wim"
  • The output shows Index, Name, and Version for each edition. Find the Index number of the edition you want (for example Windows 11 Pro). Take the number only from this file's output; the same edition may have a different index on another ISO (5.2).
  • The Version line also tells you the release: 10.0.26200.x is 25H2, 10.0.26300.x is 26H2.
  • Make sure the Gecici folder is empty. Then mount the edition, replacing <N> with the number you found. This can take a few minutes:
dism /Mount-Image /ImageFile:"C:\Mod\install.wim" /Index:<N> /MountDir:"C:\Mod\Gecici"
  • Verify the mount:
dism /Get-MountedImageInfo

Check: The output should show the C:\Mod\Gecici mount folder and Status : Ok.

If a mount is left over from an earlier attempt: If the output lists a mount that is still shown but its folder cannot be opened, run dism /Cleanup-Wim to clean up the stale mount. Then start this step again.

Step 4: Listing provisioned package names

What we are doing here: We list the provisioned apps in the image. These are the Store apps that are installed automatically for every new user account created from this image. We need this list to know exactly what to remove.

  • List the packages in the mounted image. The list is long, so save it to a file and read it there:
dism /Image:"C:\Mod\Gecici" /Get-ProvisionedAppxPackages > "C:\Mod\paketler.txt"
  • Open C:\Mod\paketler.txt in Notepad.
  • Each entry has a DisplayName (the readable app name) and a PackageName (the full name used in commands). Package names follow the pattern Name_version_architecture_~_publisherID.
  • Use this list for review only. You will select the packages to remove in the window that opens in Step 5; you do not need to copy package names.
  • Do not remove anything in this step. The Windows shell (Start, taskbar, Settings), the Microsoft Store infrastructure, and Edge/WebView2-related packages are not removal candidates.

Check: If paketler.txt contains both DisplayName and PackageName lines, the list was captured correctly.

Step 5: Selecting and removing provisioned packages in a window

What we are doing here: We select the provisioned packages you want to remove in a window. The packages you select are removed from the image's "install for new users" list. The command only removes that package from the image; it does not touch anything else installed on the system.

  • In an administrator Command Prompt, paste the following single line and press Enter. The provisioned packages open in a window:
powershell -NoProfile -Command "Add-Type -AssemblyName System.Windows.Forms,System.Drawing; $p='C:\Mod\Gecici'; $x='Store|VCLibs|NET\.Native|UI\.Xaml|AppRuntime|DesktopAppInstaller|WebView|Edge|SecHealthUI|Windows\.Client|MicrosoftWindows\.Client|ShellExperience|StartMenu|CloudExperience|AAD\.Broker|AccountsControl|LockApp|XboxIdentityProvider|Extension'; $map=@{}; $clb=New-Object System.Windows.Forms.CheckedListBox; $clb.Dock='Fill'; $clb.CheckOnClick=$true; foreach ($k in (Get-AppxProvisionedPackage -Path $p | Where-Object { $_.DisplayName -notmatch $x } | Sort-Object DisplayName)) { $d=$k.DisplayName+'  -  '+$k.PackageName; $map[$d]=$k.PackageName; [void]$clb.Items.Add($d) }; $lbl=New-Object System.Windows.Forms.Label; $lbl.AutoSize=$true; $lbl.Text=$clb.Items.Count.ToString()+' packages listed. Tick the ones to remove, then click Remove.'; $bar=New-Object System.Windows.Forms.FlowLayoutPanel; $bar.Dock='Bottom'; $bar.Height=50; $bAll=New-Object System.Windows.Forms.Button; $bAll.Text='Select all'; $bAll.Width=110; $bDel=New-Object System.Windows.Forms.Button; $bDel.Text='Remove'; $bDel.Name='kaldir'; $bDel.Width=110; $bClose=New-Object System.Windows.Forms.Button; $bClose.Text='Close'; $bClose.Width=110; $bar.Controls.AddRange(@($bAll,$bDel,$bClose,$lbl)); $f=New-Object System.Windows.Forms.Form; $f.Text='Remove provisioned packages (system packages hidden)'; $f.Size=New-Object System.Drawing.Size(900,560); $f.StartPosition='CenterScreen'; $f.Name='form'; $f.Controls.Add($clb); $f.Controls.Add($bar); $bAll.Add_Click({ for ($i=0; $i -lt $clb.Items.Count; $i++) { $clb.SetItemChecked($i,$true) } }); $bClose.Add_Click({ $f.Close() }); $bDel.Add_Click({ $sec=@(); foreach ($i in $clb.CheckedItems) { $sec+=$i }; if ($sec.Count -eq 0) { [void][System.Windows.Forms.MessageBox]::Show('No package selected.','Info'); return }; if ([System.Windows.Forms.MessageBox]::Show($sec.Count.ToString()+' package(s) will be removed from the image. Continue?','Confirm','YesNo','Warning') -ne [System.Windows.Forms.DialogResult]::Yes) { return }; $ok=0; $hata=@(); foreach ($s in $sec) { try { Remove-AppxProvisionedPackage -Path $p -PackageName $map[$s] -ErrorAction Stop | Out-Null; $clb.Items.Remove($s); $ok++ } catch { $hata+=($map[$s]+' : '+$_.Exception.Message) } }; $lbl.Text=$ok.ToString()+' removed, '+$clb.Items.Count.ToString()+' left.'; if ($hata.Count -gt 0) { [void][System.Windows.Forms.MessageBox]::Show(($hata -join [Environment]::NewLine),'Could not remove','OK','Error') } }); [void]$f.ShowDialog()"
  • In the window, tick the packages you want to remove. To tick all of them, use the Select all button.
  • Click Remove and confirm. The ticked packages are removed from the image. The window stays open, so you do not need to run the command again; removed packages disappear from the list.
  • Close removes nothing. If you close the window without confirming Remove, no package is removed either.
  • If a package cannot be removed, an error message is shown and that package stays in the list. Note the error text and try again.
  • If the window does not open, make sure you ran the command as administrator and that the mount from Step 3 is still active.
  • The Windows shell, Store infrastructure, Edge, and WebView2 packages are hidden by the filter in the window. Do not remove them (10.3).
  • Examples of packages you can remove: Microsoft.windowscommunicationsapps (Mail and Calendar), Microsoft.BingNews, Microsoft.WindowsFeedbackHub, Microsoft.MicrosoftSolitaireCollection. Names vary by version and language; use the names you see in the window.
  • Important limit: This command affects only new user accounts. Packages already installed for existing users are not removed (10.1).
  • The Windows 11 26H2 release notes also describe removing preinstalled apps through Group Policy. That is a device policy and does not replace the image method used in this guide.

Step 6: Setting the default user profile (optional)

What this step does: It sets the settings a new user sees the first time they sign in (for example dark theme and desktop icons). These settings are stored in the NTUSER.DAT registry file of the Default profile.

  • Why not write to HKCU directly? SetupComplete.cmd runs as the Local System account, so HKCU writes inside it never reach the new user. That is why we write to the Default profile file instead (9.1, 8.2).
  • The profile file is loaded and unloaded by the command itself: when the window closes, the profile is unloaded. You do not need to write reg load or reg unload. In an administrator Command Prompt, paste and run this single line:
powershell -NoProfile -Command "Add-Type -AssemblyName System.Windows.Forms,System.Drawing; $h='HKLM\MODDEFAULT'; $dat='C:\Mod\Gecici\Users\Default\NTUSER.DAT'; reg unload $h *>$null; reg load $h $dat *>$null; if ($LASTEXITCODE -ne 0) { [void][System.Windows.Forms.MessageBox]::Show('Could not load the profile. Close any open Registry Editor window and try again.','Error','OK','Error'); return }; $tema='Software\Microsoft\Windows\CurrentVersion\Themes\Personalize'; $gezgin='Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced'; $simge='Software\Microsoft\Windows\CurrentVersion\Explorer\HideDesktopIcons\NewStartPanel'; $ayar=@(@{t='Dark theme: apps';k=$tema;v='AppsUseLightTheme'},@{t='Dark theme: Start and taskbar';k=$tema;v='SystemUsesLightTheme'},@{t='Desktop: show This PC icon';k=$simge;v='{20D04FE0-3AEA-1069-A2D8-08002B30309D}'},@{t='Desktop: show Recycle Bin icon';k=$simge;v='{645FF040-5081-101B-9F08-00AA002F954E}'},@{t='Taskbar: hide Widgets button';k=$gezgin;v='TaskbarDa'},@{t='Taskbar: hide Chat button';k=$gezgin;v='TaskbarMn'}); $clb=New-Object System.Windows.Forms.CheckedListBox; $clb.Dock='Fill'; $clb.CheckOnClick=$true; foreach ($a in $ayar) { [void]$clb.Items.Add($a.t) }; for ($i=0; $i -lt $ayar.Count; $i++) { $clb.SetItemChecked($i,$true) }; $bar=New-Object System.Windows.Forms.FlowLayoutPanel; $bar.Dock='Bottom'; $bar.Height=50; $bAll=New-Object System.Windows.Forms.Button; $bAll.Text='Select all'; $bAll.Width=110; $bOk=New-Object System.Windows.Forms.Button; $bOk.Text='Apply'; $bOk.Name='uygula'; $bOk.Width=110; $bCancel=New-Object System.Windows.Forms.Button; $bCancel.Text='Cancel'; $bCancel.Width=110; $bar.Controls.AddRange(@($bAll,$bOk,$bCancel)); $f=New-Object System.Windows.Forms.Form; $f.Text='Default user profile settings'; $f.Size=New-Object System.Drawing.Size(700,420); $f.StartPosition='CenterScreen'; $f.Name='form'; $f.Controls.Add($clb); $f.Controls.Add($bar); $bAll.Add_Click({ for ($i=0; $i -lt $clb.Items.Count; $i++) { $clb.SetItemChecked($i,$true) } }); $bCancel.Add_Click({ $f.Close() }); $bOk.Add_Click({ foreach ($i in @($clb.CheckedIndices)) { $a=$ayar[$i]; & reg add ($h+'\'+$a.k) /v ($a.v) /t REG_DWORD /d 0 /f *>$null; if ($LASTEXITCODE -eq 0) { Write-Host ('Written: '+$a.t) } else { Write-Host ('NOT WRITTEN: '+$a.t) } }; $f.Close() }); try { [void]$f.ShowDialog() } finally { reg unload $h *>$null; if ($LASTEXITCODE -eq 0) { Write-Host 'Profile unloaded.' } else { Write-Host 'Could not unload the profile: close Registry Editor and try again.' } }"
  • In the window, tick the settings you want. All of them are ticked by default; untick the ones you do not want. Select all ticks them all again.
  • Apply writes the ticked settings to the profile and closes the window. The console shows a Written: line for each setting. A setting that cannot be written is shown as NOT WRITTEN:; the other settings are still written.
  • Cancel writes nothing. When the window closes, the profile is unloaded and the console shows Profile unloaded.
  • If the profile cannot be unloaded (you see a Could not unload the profile message), close any open Registry Editor window and run the command again (9.3).
  • What the settings mean:
  • Dark theme: apps and the Start menu and taskbar use the dark theme.
  • Desktop icons: This PC and Recycle Bin are shown.
  • Widgets and Chat: these buttons on the taskbar are hidden.

Note: I confirmed the Widgets and Chat values using third-party sources; I could not find them in Microsoft's official documentation. On some Windows 11 versions the Widgets value may not be writable; the command then shows NOT WRITTEN. Check the result on a virtual machine for both versions.

Step 7: Committing changes and putting install.wim back

What we are doing here: We save our changes into the image, unmount it, and then put the modified file back into the ISO's contents.

  • Close first: File Explorer windows, open files under C:\Mod\Gecici, and any Command Prompt window whose current folder is inside it (you used cd there). Open files can make unmounting fail (14.2).
  • Run the listing command from Step 4 again; the packages you removed should no longer appear.
  • Unmount with the Commit (save) option. When the command succeeds, you will see a message such as "The operation completed successfully":
dism /Unmount-Image /MountDir:"C:\Mod\Gecici" /Commit
  • If an error occurs, do not use /Discard right away. First review %WINDIR%\Logs\Dism\dism.log. /Discard throws away your changes (14.1).
  • Update the media, following the path you used:

Path A (install.wim): Move the original file to a backup folder, then copy the modified file into the media:

mkdir C:\Mod\Yedek
move "C:\Mod\Medya\sources\install.wim" "C:\Mod\Yedek\"
copy "C:\Mod\install.wim" "C:\Mod\Medya\sources\"

Path B (install.esd): Move the original install.esd to the backup folder. This matters: the media must not contain two installation images at once.

mkdir C:\Mod\Yedek
move "C:\Mod\Medya\sources\install.esd" "C:\Mod\Yedek\"
copy "C:\Mod\install.wim" "C:\Mod\Medya\sources\"

Check: dir C:\Mod\Medya\sources\install.* should show only one file, install.wim.

Step 8: Creating the ISO

What we are doing here: We package the entire Medya folder into a single ISO file. Knowing what each part of the command does helps you know what to change if something goes wrong:

  • -m: ignores the ISO size limit.
  • -o: stores identical content once instead of repeatedly, which reduces the size.
  • -u2: builds the ISO with only the UDF file system. Because install.wim is larger than 4 GiB, the classic ISO 9660 format is not enough, so UDF is required (7.3).
  • -udfver102: sets the UDF version to 1.02.
  • -bootdata:2#p0,...#pEF,...: defines two boot entries. p0 uses etfsboot.com for legacy BIOS, and pEF uses efisys.bin for UEFI. This lets the same ISO boot in either mode.
  • In an administrator Command Prompt, build the ISO. If oscdimg.exe is not on the PATH, put the full path you noted in Step 1 in quotes:
oscdimg -m -o -u2 -udfver102 -bootdata:2#p0,e,b"C:\Mod\Medya\boot\etfsboot.com"#pEF,e,b"C:\Mod\Medya\efi\microsoft\boot\efisys.bin" "C:\Mod\Medya" "C:\Mod\Custom.iso"
  • The last two paths are the source folder (C:\Mod\Medya) and the output file (C:\Mod\Custom.iso). Do not place the output inside the source folder.
  • When it finishes, record the SHA-256 hash of the ISO. You can later use it to confirm the file has not changed. Run this in PowerShell (7.4):
Get-FileHash -Algorithm SHA256 "C:\Mod\Custom.iso"

Step 9: Testing in a virtual machine

What we are doing here: We confirm that the new ISO actually installs and runs, using a virtual machine before any real device.

  • Create a virtual machine. For UEFI testing use Hyper-V Generation 2; for BIOS testing use Generation 1. Test the 25H2 and 26H2 ISOs separately (7.4).
  • Before installing, take a checkpoint of the virtual machine; if the test goes wrong, you can return to that point quickly.
  • Attach the ISO to the virtual DVD drive and boot from it.
  • When setup finishes, check: does Windows open, are the apps you removed absent from the Start menu, and do your default settings (theme, icons) appear?

Log files (for finding errors): The log location depends on the setup phase (14.1):

  • During setup, before the disk is formatted: X:\Windows\Panther\setupact.log. X: is the temporary drive of the setup environment.
  • After the disk is formatted: C:\Windows\Panther\setupact.log.
  • During the user settings (OOBE) phase: C:\Windows\Panther\UnattendGC\setupact.log.

Final note: Do not write an ISO that fails testing to physical media. For troubleshooting, see the matrix in 14.2.
